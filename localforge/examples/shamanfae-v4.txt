==========================================================
DEFECT PATTERNS THAT HAVE ALREADY COST THIS PROJECT DAYS
==========================================================
Every one of these shipped in a previous run. They are cheap to avoid and expensive to find.

- FALSY GUARDS ON NUMBERS. `if (!startQ) return []` is true when startQ is 0. The unit stands at (0,0), so this one line silently disabled all pathfinding for an entire twelve-hour run. Guard with `== null` or a type check, never with `!`.
- BUILDING A SUBSYSTEM AND NEVER CONNECTING IT. An encounter system was constructed, then never given state, never triggered, never drawn, and never clickable. If you add a system, wire all of its ends in the same task and prove it fires.
- SPLITTING DRAWING FROM HIT-TESTING. Option buttons were drawn from one set of numbers and hit-tested from another, and the hit-tester was left returning null forever. Derive both from one shared layout function.
- DROPPING THE CAMERA TRANSFORM. World-space layers must draw inside `ctx.translate(camera.x, camera.y)`; screen-space layers (HUD, modals) must draw outside it. Omitting it puts the whole map off the corner of the canvas while the HUD still looks fine.
- MODULE-SCOPE DOM ACCESS. Only `main.js` may have side effects at import time. Every other module exports functions and does nothing when imported — no `document.createElement`, no `addEventListener`, no object construction at module scope. Build sprites lazily on first use and memoise.
- SWALLOWING ERRORS. A `try/catch` that logs `console.warn` and continues hid a method call to a function that never existed, firing sixty times a second for twelve hours. Do not catch what you have not handled.
- COSMETIC EFFECTS THAT DESTROY LEGIBILITY. A transition-gradient pass stacked translucent hexes over every terrain boundary until the whole map was one undifferentiated green. If an effect reduces terrain distinctness, it is a regression no matter how nice the idea was.

The build is checked in a real browser after every task. It must have zero uncaught page errors and zero console errors, and it is also measured for:

- DEAD PLAY AREA — the centre 60% of the canvas being one flat colour while the edges have content. A HUD rendering over an empty map fails here. This is a hard failure.
- RESPONDS TO INPUT — whether clicking the canvas changes anything beyond idle animation. A build that renders beautifully and ignores the mouse is not done.

Before claiming any task complete: load the page, confirm the map is visible, and confirm a click still moves the Shaman-Chief. If your change broke movement, you have not finished the task, whatever it looks like in a screenshot.

ART DIRECTION
==========================================================
A deliberate limited palette — earthy Bronze Age tones for the tribe against cold, unnatural Fae colours, cohesive and slightly muted. All colours come from `src/palette.js` as named exports; no hard-coded colour strings anywhere else. Hex tiles must read as distinct terrain at a glance, with clean edges and no muddy seams. Every unit and marker must be instantly distinguishable from the tile beneath it. UI is diegetic and readable: carved bone and woad stain, not default browser widgets. Game feel: hover highlights, smooth movement tweens, a subtle pulse on the active unit, particle flourishes on ritual casts.

Fan out sub-agents to work in parallel. /loop on each item with a harsh critic checking it visually until it reads as a polished commercial indie strategy game, not programmer art. Ultracode.

SHAMAN-CHIEF FAE REALM – COMPLETE GAME DESIGN DOCUMENT
==========================


VERSION: 1.0
TARGET ENGINE: GODOT 4.6.X
PLATFORMS: PC (Windows/macOS), Mobile (iOS/Android)
GAME TYPE: Turn-Based Strategy / Survival / Narrative


----------------------------------------------------------
1. GAME OVERVIEW
----------------------------------------------------------
You play as the Shaman-Chief of a Bronze Age nomadic tribe that has wandered into the land of the Fae. The goal is to either escape the realm or find a safe place to build a society and stop wandering. The game is played on a hex-based map and combines strategy, resource management, narrative encounters, ritual magic, and dynamic Fae politics.


Key Features:
- Turn-based strategy with dynamic tile regeneration
- Ritual magic system (Bind, Bargain, Banish, Blessings)
- Spirit system: deceased Shaman-Chiefs provide aid
- Tribe management: roles, aging, death, tasks
- Fae Courts: Seelie, Unseelie, Wild
- Encounter library: 120+ events with chaining and mutating mechanics
- Multiple game lengths (Short, Medium, Long, Epic, Endless)
- Scoring system with cumulative stats


----------------------------------------------------------
2. CORE SYSTEMS
----------------------------------------------------------
2.1 Hex Map
- Hex grid of tiles
- Tile properties: terrain type, encounter type, visited boolean, regeneration counter, Court influence
- Visibility: 
  - Explored tiles: fully visible
  - Adjacent tiles: terrain + encounter type hint
  - Outer ring: terrain only
- Tile regeneration: 
  - Starts after ≥5 turns since last visit
  - Base 10% chance per turn to regenerate encounter, +2% per extra turn (max 50%)
  - Mutates based on Weirdness and Court influence


2.2 Shaman-Chief
- Single role and unit: leader and shaman
- Attributes: Health, Magic Pool, Morale, Skill/Aptitude, Status/Conditions
- Actions:
  - Move (1 turn, 1 food/water per member)
  - Rest (1 turn, 1 food/water)
  - Rituals (Minor/Major Blessings, Bind, Bargain, Banish)
  - Forage/Explore (1 turn)
- Spirit Continuation:
  - Upon death, a new Shaman-Chief takes over
  - Deceased Shaman-Chiefs become spirits providing bonuses:
    - +1 magic per turn per spirit
    - Minor morale boost
    - Can be sacrificed for rituals


2.3 Tribe Members
- Roles: Hunter/Gatherer, Scout/Pathfinder, Warrior/Protector, Craftsman/Builder
- Attributes: Health, Morale, Age
- Aging: Child → Adolescent → Adult → Elder → Ancient
- Death impacts morale and efficiency
- Assignable to tasks for resource collection, ritual support, defense, or exploration


2.4 Resources
| Resource     | Function                                      | Notes |
|--------------|-----------------------------------------------|-------|
| Food/Water   | Sustains population                           | Low → health/morale penalty |
| Morale       | Tribe cohesion                                | Boosted by success, rituals, Spirit aid; reduced by deaths/failure |
| Population   | Supporting members                            | Drives efficiency, ritual support |
| Materials    | Crafting, rituals                             | Gathered by tribe roles |
| Magic        | Shaman-Chief pool                             | Used for rituals; boosted by Spirit aid |
| Weirdness    | World instability                             | High → mutated encounters & terrain |
| Court Favor  | Seelie / Unseelie / Wild                      | Modifies encounter outcomes & ritual success |


2.5 Turn Structure
- **Start-of-Turn**: Consume resources, apply Weirdness, update Court influence, Spirit effects
- **Decision Phase**: Shaman-Chief chooses actions (move, rituals, forage, Bind/Bargain/Banish)
- **Encounter Phase**: Trigger tile encounters
- **Aftermath Phase**: Apply delayed effects, Spirit bonuses, queued chain encounters
- **End-of-Turn**: Update turn counter, UI, check victory/defeat, scaling


----------------------------------------------------------
3. RITUAL & MAGIC SYSTEM
----------------------------------------------------------
Rituals can be Minor Blessings, Major Blessings, Bind, Bargain, Banish, Environmental, Weird Manipulation.


- **Bind**: 1 magic, temporarily control Fae/Wild effect
- **Bargain**: 1 magic, negotiate with Fae
- **Banish**: 2 magic, remove threat
- **Minor Blessing**: 1 magic, heal or small resource gain
- **Major Blessing**: 2–3 magic, substantial benefit
- **Environmental Rituals**: 1–3 magic, modify tile effects
- **Weird Manipulation**: 2–5 magic, alter Weirdness


Modifiers:
- Shaman-Chief skill, Tribe support, Court favor, Weirdness, Spirit aid, Material components
- Outcomes: Full success, Partial success, Failure (Weirdness spike, injury, Court reaction)


----------------------------------------------------------
4. SPIRIT SYSTEM
----------------------------------------------------------
- Deceased Shaman-Chiefs provide passive bonuses (+magic/turn, morale)
- Sacrificable in rituals for greater effect
- Stackable
- Influence tile regeneration, encounter outcomes, and ritual success


----------------------------------------------------------
5. ENCOUNTERS
----------------------------------------------------------
- Library: 120+ encounters, some chained by story
- Triggered by tile terrain, tier, Court influence, Weirdness, story tags
- Chain encounters triggered by prior actions or rituals
- Regeneration after ≥5 turns
- Can mutate based on Weirdness + Court influence
- Spirit aid can stabilize/amplify outcomes


----------------------------------------------------------
6. COURT INFLUENCE
----------------------------------------------------------
- Three Courts: Seelie, Unseelie, Wild
- Tiles have Court influence values (0–100 per Court)
- Influence spreads ±5–10 per turn to adjacent tiles
- High favor affects encounter difficulty, ritual success, chain events
- All Fae associated with a Court, even lone or unaffiliated Fae


----------------------------------------------------------
7. GAME LENGTHS & SCALING
| Mode    | Turn Range | Notes |
|---------|-----------|-------|
| Short   | 20–25     | Focused runs |
| Medium  | 30–36     | Default balance |
| Long    | 45–50     | Extended strategy |
| Epic    | 100+      | Deep challenge, generational |
| Endless | ∞         | No victory; wander until tribe perishes |


- Game balanced around Medium length
- Resources, Weirdness, and encounter difficulty scale with turn count


----------------------------------------------------------
8. SCORING
----------------------------------------------------------
- Hidden per-run calculation
- Tracked metrics:
  - Tiles discovered
  - Years traveling
  - Largest tribe population
  - Most Weirdnesses encountered
  - Total time played
  - Quests completed, Fae favor
- End-of-run display:
  1. Score this run
  2. Best score from all previous runs
  3. Total cumulative score across all runs

9. GAMEFLOW & UI
----------------------------------------------------------
**Launch sequence**
- Fade in company logo → fade out → main menu


**Main Menu**
- New Game → select journey length → start game
- Continue → load last save
- Settings → sound/graphics/resolution
- Exit → closes game


**Gameplay Area – 4 Windows**
1. Hex Map Window
   - Hex grid with tile selection
   - Resource bar + buttons (Tribe, Settings)
   - Pan map / select tile → triggers move/encounter


2. Tribe Window
   - Shows tribe members, resources, quests, promises, rituals
   - Assign tasks and resources
   - End turn / return to map


3. Encounter Window
   - Triggered by entering a hex with a challenge
   - Top: picture background (terrain, tribe right, Fae left, optional items center)
   - Bottom: text + options, costs/bonuses displayed
   - Resolution shows gains/losses and updates resources
   - Persists until dismissed → returns to Tribe Window


4. Settings Window
   - Mirrors main menu settings + Exit game button


**Controls**
- Mobile: tap, swipe, pinch-zoom
- PC: click, hotkeys


**Save System**
- Auto-save on moving to a new tile
- Includes: turn, tile map, Shaman-Chief stats & spirits, tribe member stats, resources, quests
